一、架构决策与数据流

1.1 决策：独立 crate，对齐 ncm-api-rs 先例

方案说明优点缺点结论
A. 独立 crate
native/qqkg-api/		 新建 crate，headless-server 以 path 依赖引入 对齐 ncm-api-rs 先例（395 文件 / 12000 行的成熟结构）；加密层可独立 cargo test；不污染 headless-server；后续 M4 扩端点只加文件 比内嵌多约 0.5~1 天（骨架 + 单测搭建） 采用

/// 前端 type 参数 → 内部枚举 → 各平台上游 search_type
pub enum SearchType { Song, Album, Artist, Playlist }

impl SearchType {
    /// 兼容数字(0/2/8/9)与字符串两种入参形态
    pub fn from_param(v: &Value) -> Self {
        match v.as_i64().or_else(|| v.as_str().and_then(|s| s.parse().ok())) {
            Some(8)  => Album,
            Some(9)  => Artist,
            Some(2) | Some(3) => Playlist,
            _ => Song,
        }
    }
    /// QQ 上游映射：单曲0 / 歌手1 / 专辑2 / 歌单3（桌面端同款）
    pub fn qq_search_type(&self) -> i64 { match self { Song => 0, Artist => 1, Album => 2, Playlist => 3 } }
}

四、加密层实现规格

4.1 酷狗签名 kg_sign.rs（≈55 行，M0）

const KG_WEB_SALT: &str = "NVPh5oo715z5DIWAeQlhMDsWXXQV4hwt";        // 网关 signature 用
const KG_SIGN_KEY_SALT: &str = "57ae12eb6890223e355ccfcb74edf70d";   // song_url 的 key 用

/// 参数名 ASCII 升序拼 k=v，首尾加盐后 MD5（对齐 crypto.ts）
pub fn signature_web_params(params: &[(String, String)]) -> String {
    let mut sorted = params.to_vec();
    sorted.sort();
    let mut s = String::from(KG_WEB_SALT);
    for (k, v) in sorted { s.push_str(&k); s.push('='); s.push_str(&v); }
    s.push_str(KG_WEB_SALT);
    format!("{:x}", md5::compute(s.as_bytes()))
}

md5 crate(0.7)已在 headless-server 依赖中，crate 内再声明同版本。盐值常量从桌面端 kugou/core/crypto.ts / config.ts 原样复制。

4.2 酷狗 RSA no-padding kg_rsa.rs（≈75 行，M0）

use num_bigint_dig::BigUint;

/// RSA-1024 NO_PADDING：JSON 明文 → 128 字节零填充块 → 模幂 → hex 大写
pub fn rsa_encrypt_kugou(plaintext: &str) -> String {
    const N_HEX: &str = "/* 从桌面端 crypto.ts 公钥常量区原样复制 */";
    let n = BigUint::parse_bytes(N_HEX.as_bytes(), 16).unwrap();
    let e = BigUint::from(65535u32 + 2u32);  // 65537

    let bytes = plaintext.as_bytes();
    let mut block = [0u8; 128];
    // 填充方向（左/右）以桌面 crypto.ts 实现为准，用 Node 对照测试锁定（见 4.5）
    block[128 - bytes.len()..].copy_from_slice(bytes);

    let c = BigUint::from_bytes_be(&block).modpow(&e, &n);
    c.to_str_radix(16).to_uppercase()
}

用 num-bigint-dig 的 modpow 而非拉全 rsa crate——no-padding 场景只需要一次模幂，70 行内解决。用途：user_detail 的 p 参数、S3 song_url 的 key。

4.3 酷狗 MID kg_mid.rs（≈25 行，M0）

首版直接采用桌面端默认 GUID 对应的固定 mid 常量（模拟稳定设备指纹，降低风控概率）；后续若被风控再实现 GUID→MD5→大整数进制转换的完整算法。

4.4 QQ 3DES qq_des.rs（≈200 行，M3-QQ）

项规格
算法3DES-CBC（EDE3），自定义填充——密钥/IV/填充常量从桌面端 qqmusic/core/tripledes.ts（421 行）常量区原样移植

    ③ calculateMid 的 MD5 hex 视作 128 位无符号大整数转十进制，u128::from_str_radix 即可（无需 bigint）；设备指纹 DEVICE_MID = 313977252576711075203126132950927082200
  • 依赖：md5/num-bigint-dig/num-traits（Num::from_str_radix 所需，未 re-export）/serde/thiserror；M0 未引入 reqwest（M1 随客户端模块再加）
  • Cargo.lock 已入库（独立 crate 的可复现构建）
